# 个人网站需求说明（优化版）

> 目标站点：xikiyworkshop.xyz
> 这份文档可以直接作为开发提示词，也可以作为后续开发的需求基线。

## 一、项目总览

做一个个人网站，包含 6 类页面：首页、博客列表、博客详情、时间轴、云盘、友链。整体要求是：

- 强视觉体验、丰富动效，但动效不阻塞阅读、不造成布局抖动，并尊重 `prefers-reduced-motion`。
- 结构高度模块化、可扩展：以后新增页面或功能时，不修改或尽量少修改已有页面。
- 博客、云盘、友链页面为白色色调；所有卡片使用圆角和极浅阴影。
- 支持开发模式与生产模式分离：开发环境是动态编辑网站；生产构建是纯静态网站，且静态产物中不出现任何开发模式的功能、按钮或入口。

## 二、技术架构建议

已确认的决策：

- 技术栈实现优先，默认采用 Next.js（App Router）+ TypeScript + Tailwind CSS。
- 内容不放数据库，也不拆独立私有仓库；文章使用 Markdown/MDX 文件直接放在站点仓库中管理。
- 访客数、浏览量统计复用已有组件（Busuanzi / Umami 等），不自己造轮子。
- 首页视觉风格为插画手绘风。
- 云盘页内提供独立的文件搜索，不与其他页面搜索混用。

实现原则：

- 内容使用 Markdown/MDX + frontmatter 管理，统一封装内容读取层，页面不直接依赖文件路径。
- 所有站点配置集中管理：站点信息、个人信息、导航、格言、友链、云盘目录、统计数据。
- 图片和云盘文件使用 Cloudflare R2 对象存储；云盘页面通过 R2 公共链接或预生成的文件清单展示。
- 环境变量 `DEVELOPER_MODE`，默认 `false`：
  - `true`：启用开发模式，显示动态编辑能力；
  - `false`：构建纯静态站点，开发模式相关代码、按钮、路由全部从产物中排除，而不是仅隐藏。

## 三、全局 UI 与交互规范

- 顶端导航栏：最左侧为 `XikiyWorkshop`；右侧依次为 搜索、首页、博客、云盘、友链。
- 导航栏行为：
  - 页面下滑时自动隐藏，上滑时自动出现；
  - 当导航栏位于首页 hero、博客大背景图或其他页面顶部图片区域内时，背景自动过渡为透明；离开图片区域后恢复为半透明或白色背景。
- 移动端导航收起为菜单按钮。
- 卡片统一圆角 + 极浅阴影，悬停动效保持一致。
- 博客、云盘、友链页面保持白色为主，图片区域可以有视觉冲击力，但内容区保持干净可读。

## 四、页面需求

### 1. 首页

- 全屏 hero 区域，展示：自我介绍、格言、技术栈。
- 需要很强的视觉体验和动效，整体采用插画手绘风格：
  - 全屏手绘插画 hero，使用真实插画素材作为背景；
  - 手写体标题与格言，格言可带打字机动画；
  - 手绘描边、纸张/水彩质感、涂鸦感的小装饰；
  - 技术栈以手绘徽章、贴纸或卡片墙形式展示；
  - 滚动驱动的文字渐显、视差和内容入场动画；
  - 提供进入博客、云盘、友链的醒目入口。
- 页面结构建议：hero → 自我介绍 → 格言 → 技术栈 → 快速入口。

### 2. 博客列表页

- 整屏自定义背景图，图片固定不滚动。
- 背景图正中间偏上一点的位置：
  - 第一行：`Xikiy‘s blogs`
  - 第二行：`以砺为阶，无限进步！`
- 页面底部有“下滑查看”的指引。
- 浏览器视口底部开始进入博客区域；文字区域和博客区域是一体的，上滑时一起离开屏幕，背景图始终保持不动。
- 左侧信息区，共 5 张卡片：
  1. 个人信息卡，自上而下：
     - 头像；
     - 网名；
     - 签名；
     - 文章总数、标签总数、分类总数；
     - 蓝色长方形按钮，按钮内容为 GitHub 图标 + `Follow Me`；悬停时按钮颜色从蓝色过渡到橙色，并略微放大；
     - GitHub 图标；
     - `<img src="https://count.getloli.com/@LuviaSeraphina?theme=rule34" alt="LuviaSeraphina" />` 访客计数组件。
  2. `Current Target` 卡片：展示当前规划。
  3. 分类卡片：按分类归纳文章，点击分类进入该分类的时间轴界面。
  4. 标签卡片：标签词云，点击标签进入对应标签的时间轴界面，按时间顺序展示含该标签的文章。
  5. 网站信息卡片：网站访客数、总浏览量、最后更新时间。
- 右侧为博客卡片区域：
  - 卡片包含自定义封面图 + 信息区；
  - 信息区第一行是标题，第二行是 `发表时间 | 分类`（无分类时只显示发表时间），第三行是文章开头摘要；
  - 图片和信息位置左右交替：第一张图左文右，第二张图右文左，依次交替；
  - 鼠标悬停时卡片略微放大。

### 3. 博客详情页

- 页面顶部约 3/7 视口高度位置放置自定义封面图。
- 图片下方区域：
  - 第一行：文章标题；
  - 第二行：`发表时间 | 更新时间 | 分类`；
  - 第三行：浏览量。
- 图片下方为正文区域。
- 信息区仅保留：个人信息卡、未来规划卡、网站数据卡，并新增目录卡。
- 目录卡：
  - 卡片标题为 `目录`，同一行右侧实时显示当前阅读百分比；
  - 在浏览器顶部往下 2/7 的位置设置隐形判定线；
  - 当正文进入判定线后开始计算阅读百分比，并实时更新数字；
  - 判定线扫过文章中的标题时，目录同步高亮当前标题；
  - 当个人信息卡和未来规划卡滚动出顶部后，目录卡仍保持固定在界面中，继续实时显示当前阅读位置，直到阅读到 100%。
- 正文底部增加作者与版权框：
  - 第一行：`文章作者：LuviaSeraphina`
  - 第二行：`本博客所有文章除特别声明外，均采用 CC BY-NC-SA 4.0 许可协议。转载请注明来源Xikiy's blog`；
  - 其中 `CC BY-NC-SA 4.0` 链接到 `https://creativecommons.org/licenses/by-nc-sa/4.0/`；
  - `Xikiy's blog` 链接到博客首页。

### 4. 时间轴页

- 页面顶部约 3/7 视口高度位置放置自定义图片，图片正中间显示 `Timeline`。
- 时间轴从最新到最旧排序，按年份分组，风格类似朋友圈时间线：
  - 一条纵向主轴；
  - 年份为大类；
  - 每个日期/月份下放置对应的博客文章卡片，位于日期右侧；
  - 同一天有多篇文章时，最新的文章卡片排在该日最上方。
- 分类时间轴和标签时间轴复用同一套时间轴组件，只按分类或标签过滤文章。

### 5. 云盘页

- 页面顶部约 3/7 视口高度位置放置自定义图片，图片正中间显示 `妙妙R2对象存储`。
- 信息区仅保留：个人信息卡、未来规划卡、网站数据卡；其中个人信息卡第四行数据改为显示 R2 存储桶大小，格式为 `xxx MB` 或 `xxx GB`。
- 云盘区域按文件夹形式展示：
  - 文件夹默认收起，点击展开；
  - 展开后展示其中的子文件夹和文件；
  - 根文件夹名为 `xikiy-bucket/`，默认展开；
  - 点击文件名称即可从 R2 对象存储链接自动下载；
  - 云盘区域顶部提供独立的搜索框，只搜索云盘内的文件夹名和文件名；搜索结果可直接定位或下载。

### 6. 友链页

- 信息区仅保留：最初的个人信息卡 + 未来规划卡。
- 友链区域：
  - 第一个大标题：`友情链接`；
  - 下方是链接按钮，点击跳转到指定链接；
  - 按钮左侧为自定义图片，右侧两行信息：第一行网站名或昵称，第二行描述。
- 第二个大标题：`宝藏链接`，同样使用左图右文的按钮。

### 7. 页脚

- 所有页面底部显示：`© 2026 LuviaSeraphina. All rights reserved`

## 五、开发模式（DEVELOPER_MODE=true）

开发模式是动态网站，需要提供易用的管理能力：

- 博客管理：创建、编辑、删除文章，支持设置标题、封面、分类、标签、摘要、正文、发布时间/更新时间。
- 图片管理：上传图片、调整/裁剪图片，支持随时更换头像、文章封面、页面顶部图片和博客背景图。
- 云盘管理：在云盘中新建文件夹、文件或外部下载链接，并调整目录结构。
- 配置管理：编辑格言、自我介绍、签名、Current Target、友链、宝藏链接、导航等站点数据。
- 数据导出：开发模式下完成编辑后，可以生成/导出正式数据，再进行生产构建。

生产构建（`DEVELOPER_MODE=false`）必须满足：

- 输出纯静态预构建产物；
- 静态产物中不出现开发模式的管理入口、编辑按钮或相关路由；
- 所有页面仍可完整浏览。

## 六、数据模型建议

- 文章：`slug`、`title`、`date`、`updated`、`category`、`tags`、`cover`、`excerpt`、`content`。
- 个人信息：`avatar`、`name`、`signature`、`github`、`stats`。
- 站点信息：`visitors`、`views`、`lastUpdated`、`r2BucketSize`。
- 云盘：树形结构，节点分为文件夹和文件，文件包含 `name`、`url`、`size`。
- 友链：`name`、`description`、`url`、`image`。
- 导航与站点配置：集中维护，新增页面时只扩展配置和路由。

## 七、验收清单

- 所有页面、导航、页脚按上述规格实现。
- 导航栏透明、隐藏/显示逻辑正确。
- 博客列表左右信息区、卡片交替、悬停放大均正确。
- 文章页阅读百分比、目录高亮、目录吸顶直到 100% 均正确。
- 时间轴、分类时间轴、标签时间轴数据正确且排序正确。
- 云盘文件夹展开/收起、文件下载可用，云盘内独立搜索可用。
- 友链按钮跳转与展示正确。
- `DEVELOPER_MODE=true` 时管理功能可用；`false` 构建出的静态站无任何开发功能残留。

## 八、已确认决策与说明

1. 技术栈：实现优先，默认 Next.js + TypeScript + Tailwind CSS。
2. 文章存放：不放数据库，也不拆独立私有仓库。文章以 Markdown/MDX 文件存放在站点仓库，理由：
   - 本项目最终构建纯静态站点，Markdown 文件在构建时读取最自然，部署简单；
   - Git 本身就是版本管理，能保留文章修改历史，无需再维护数据库；
   - 开发模式中的博客编辑器直接读写 Markdown 文件即可，保存后重新构建生效；
   - 数据库适合需要实时发布、评论、多人协作或大规模内容的场景，对个人博客是额外复杂度；
   - 单独私有仓库会增加跨仓库同步和构建时的权限处理，当前单人维护没有必要。
3. 访客数和浏览量统计：复用已有组件（Busuanzi / Umami 等）。
4. 首页视觉风格：插画手绘风。
5. 搜索：云盘页内单独提供云盘文件搜索。
